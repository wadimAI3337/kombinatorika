# Диаграммы из отсканированной шахматной книги → FEN

Пайплайн, которым были получены 600 позиций из книги В. Конотопа
«Тесты по тактике для шахматистов II разряда» (скан, текстового слоя нет).

Результат: 600 FEN, все прошли проверку на легальность; расхождений с
авторскими решениями после перепроверки — ноль.

---

## Сначала главное: два разных случая

**PDF с текстовым слоем** (текст выделяется мышкой). Диаграммы там —
векторные символы шахматного шрифта. Тогда всё делается через PyMuPDF:
`page.get_text("dict")` даёт координаты и коды глифов, фигура и клетка
вычисляются арифметикой. Это минуты работы, компьютерное зрение не нужно.
Проверить: `pdffonts book.pdf` — если в списке есть шахматный шрифт
(Chess Diagrams, FigurineSymbol и т.п.), случай этот.

**Скан** (страница = одна картинка). Тогда — всё, что описано ниже.
Проверить: `pdfimages -list book.pdf | head` — одна большая картинка на
страницу и никакого текста.

---

## Логика: почему именно так

Наивный подход «обучить классификатор фигур» разбивается о то, что
размеченных данных нет и взять их неоткуда. Поэтому ставка сделана на три вещи:

**1. Геометрия доски жёсткая.** 8×8, клетки одинаковые, рамка — сплошная
тёмная линия. Значит сетку можно посадить точно, а не «примерно»,
и дальше каждая фигура приходит в своё окно почти без разброса.
Точность сетки — самая важная часть всего пайплайна: сдвиг на 2 пикселя
затягивает в клетку кусок рамки, и дальше ломается всё.

**2. Изображений фигур мало — их 12.** Если клетки выровнены, k-means
на сырых пикселях даёт чистые кластеры. Разметить 420 усреднённых
картинок глазами — 20 минут. Это дешевле, чем любая разметка обучающей
выборки, и точнее, чем любой готовый OCR.

**3. Шахматные правила — бесплатный валидатор.** Ровно один король у
каждой стороны, не больше 8 пешек, нет пешек на крайних горизонталях.
Ошибка распознавания почти наверняка ломает одно из этих условий.
Это и ловит ошибки, и чинит их: локальный поиск по «перекрасить кластер»
сам находит кластеры, у которых перепутан цвет.

## Где реально ломается (и что с этим делать)

Это список граблей — на них ушло больше всего времени.

**Сетка съезжает, если искать её по контрасту клеток.**
Мера «средняя яркость светлых клеток минус тёмных» считается по центрам
клеток и почти не меняется при сдвиге на ±2 px. Итог: в 1-ю горизонталь
залезает нижняя рамка, в линию h — правая. Лечится вторым проходом
(`lib_refine.py`): найти внутренние края рамки по профилю черноты и
взять их как границы доски. Высоту и ширину клетки считать РАЗДЕЛЬНО —
скан бывает неквадратным (у нас до 4% разницы).

**Белая фигура и чёрная различаются заливкой, а не формой.**
Белая — контур, чёрная — залита. Значит любое усреднение убивает признак.
Мы сначала сжимали клетку до 24×24 со сглаживанием — и белый ферзь стал
неотличим от чёрного (зубцы короны тоньше 4 px). Правило: до кластеризации
не уменьшать картинку сильнее, чем вдвое, и не сглаживать сильнее σ≈0.8.

**Порог «чернила» нельзя брать абсолютный.** Тёмные клетки на растре
печатаются точками, их средняя яркость ~180, светлые ~250. Порог считается
от фона КОНКРЕТНОЙ клетки: медиана по всем клеткам этой чётности на этой
доске.

**Занятость клетки надёжнее считать по площади чернил, а не по силуэту.**
Силуэт белой фигуры (заливка контура) рвётся, если контур где-то разомкнулся
сканом, — площади скачут от 120 до 1200. А площадь чернил даёт чистый разрыв:
0 у пустых клеток, ≥200 у занятых, между 1 и 170 — полтора десятка клеток
на 38 400. Порог ставится в этот зазор.

**Мелкий мусор.** Растровые точки на тёмных клетках и обрывки рамки.
Убираются как связные компоненты меньше 18 px и как «узкие полоски,
касающиеся края клетки». Морфологическое открытие тут НЕ годится — оно
съедает тонкий контур белых фигур.

**Плохие сканы честнее перебить руками.** Из 600 досок 6 были настолько
контрастно убитыми, что кластеризация путала на них ферзя с королём.
Все «далёкие» от центроида клетки оказались именно на этих шести досках —
то есть расстояние до центроида работает как детектор «сюда посмотри глазами».

## Шаги

| скрипт | что делает |
|---|---|
| `01_pdf_to_pages.py` | PDF → PNG страниц (`pdfimages`, один вызов на диапазон) |
| `02_find_boards.py` | находит рамки диаграмм на странице, режет доски и подписи |
| `03_grid_coarse.py` | грубая посадка сетки 8×8 (контраст чётности клеток) |
| `04_grid_refine.py` | точная посадка по внутренним краям рамки → клетки 48×48 |
| `05_segment.py` | фон, чернила, силуэт, занятость клетки |
| `06a_normalize.py` | нормализация яркости + центрирование по центру масс |
| `06b_cluster.py` | k-means (k≈420) + контактные листы для ручной подписи |
| `labels_example.py` | ← сюда вписываются 420 букв (K Q R B N P k q r b n p X) |
| `07_constraint_search.py` | локальный поиск: чинит перепутанный цвет кластера |
| `08_build_board.py` | кластер → буква → матрица 600×64 |
| `00_sanity_check.py` | проверка шахматными правилами (запускать после 08) |
| `09b_turn.py` | чей ход — из подписи «1. ?» / «1. ... ?» |
| `09_build_fen.py` | сборка FEN (+ рокировки по положению короля и ладей) |
| `10_validate_vs_solutions.py` | сверка ходов из решений с позициями |

Порядок: 01 → 02 → 03 → 04 → 05 → 06a → 06b → **руками подписать кластеры**
→ 07 → 08 → 00 → 09b → 09 → 10.

## Ручной шаг — единственный

После `06b_cluster.py` появляются `sheet_00.png … sheet_14.png`:
по 28 усреднённых картинок кластеров на листе, 7 в ряд.
Их надо прочитать и выписать 420 букв в том же порядке (слева направо,
сверху вниз) в `labels_example.py`.

Обозначения как в FEN: заглавные — белые (K Q R B N P), строчные —
чёрные (k q r b n p), `X` — мусор (обрывок рамки, пятно).

Как отличать на усреднённой картинке:
* **король** — корона с двумя круглыми «ушами» и шариком с крестом сверху;
* **ферзь** — корона с пятью зубцами;
* **белый / чёрный** — у белого «уши» и зубцы ПУСТЫЕ (контур), у чёрного залиты;
* **ладья** — у белой корпус белый, у чёрной чёрный;
* смазанный, «двоящийся» центроид = кластер грязный, лучше поднять k.

После этого `07_constraint_search.py` сам найдёт кластеры, где цвет
перепутан: он перебирает «перекрасить кластер в противоположный цвет»
и оставляет замену, если суммарное число нарушений шахматных правил
по всем 600 доскам падает. У нас так нашлись 5 ошибок подписи
(стоимость упала с 2714 до 46), дальше 3 клетки поправлены руками.

## Проверка результата

Три независимых проверки. Каждая ловит своё:

1. **Шахматные правила** (`00_sanity_check.py`) — ловит грубые ошибки:
   лишний король, пешка на 8-й горизонтали.
2. **Легальность FEN** (`python-chess`, `Board(fen).was_into_check()`) —
   ловит позиции, где сторона, которая НЕ ходит, стоит под шахом.
   Это невозможно в реальной партии, значит либо фигура прочитана неверно,
   либо перепутана очередь хода.
3. **Проигрывание авторских решений** (`10_validate_vs_solutions.py`) —
   самая сильная проверка. Ходы из текста решений подставляются в позицию
   и проверяются на легальность. Два независимых источника (картинка
   диаграммы и текст решения) должны сойтись.

Третья проверка нашла у нас 25 расхождений: 23 — опечатки распознавания
текста, 2 — реально неверно прочитанные фигуры на диаграмме. Без неё эти
две позиции остались бы битыми.

Отдельный приём: если ход из книги в позиции нелегален, перебрать
однобуквенные замены (`c`↔`e`, `b`↔`h`, `d`↔`b`, `3`↔`8`) и посмотреть,
даёт ли ровно один вариант легальный ход. Если да — это опечатка OCR,
и она чинится автоматически. У нас так починилось 19 ходов из 25.

## Зависимости

```
pip install numpy pillow scipy scikit-learn python-chess
apt install poppler-utils           # pdfimages, pdffonts, pdftotext
```

Тексты решений (если они тоже сканом) OCR-ом брать можно, но **только прозу**:
`tesseract -l rus+eng`. Шахматные ходы он ломает — путает поля d/f/g с цифрами
и не видит значки фигур. Ходы надо вычитывать по картинке; в `prompt_transcribe.md`
лежит инструкция, по которой это делалось.
