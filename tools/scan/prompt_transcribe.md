# Промпт для расшифровки страниц с решениями

Использовался для параллельных под-агентов: каждый брал свои 6–8 страниц,
смотрел картинку и набирал текст. Страница заранее резалась на две
перекрывающиеся половины (0–53% и 47–100% высоты) — так мелкий шрифт
читается увереннее.

---

Ты расшифровываешь отсканированные страницы русской шахматной книги (раздел «ОТВЕТЫ»).

РАБОЧАЯ ПАПКА: <путь>

ТВОИ СТРАНИЦЫ: 013, 014, 015, 019, 020, 021, 022, 023

Для каждой страницы NNN:
1. Прочитай картинку `sol_img/pNNNa.png` (верхняя часть) и `sol_img/pNNNb.png` (нижняя).
   Части ПЕРЕКРЫВАЮТСЯ примерно на 6% высоты — не дублируй строки, видные в обеих.
2. Файл `sol_ocr/pNNN.txt` — черновик OCR, можно прочитать, чтобы быстрее набирать
   имена собственные и прозу. НО OCR сильно врёт в шахматных ходах — ходы бери
   ТОЛЬКО с картинки глазами.
3. Запиши результат в `sol_txt/pNNN.txt`.

ФОРМАТ ВЫХОДНОГО ФАЙЛА:
- Номер страницы внизу листа НЕ переносить.
- «ТЕСТ №K» — отдельной строкой: `[[TEST K]]`
- Начало решения («№1 Фамилия – Фамилия, Город, Год») — как:
  `[[N 1]] Биргисдоттир – Батуяг, Сегед, 1994`
- Дальше текст сплошняком; переносы слов (дефис в конце строки) склеивать.
- Если страница НАЧИНАЕТСЯ с середины решения — первой строкой `[[CONT]]`.
- «(1 очко)» / «(2 очка)» / «(3 очка)» сохранять.

ШАХМАТНАЯ НОТАЦИЯ — САМОЕ ВАЖНОЕ:
- Значки фигур заменяй латиницей: король → K, ферзь → Q, ладья → R, слон → B, конь → N.
  Контурные (белые) и залитые (чёрные) значки дают одну и ту же букву.
- Поля пиши латиницей a1–h8. OCR подменяет латиницу кириллицей и цифрами
  (d→«4», f→«£»/«3», g→«5», b→«Ь») — ИСПРАВЛЯЙ по картинке.
- Сохраняй как напечатано: двоеточие для взятия (N:c2+), «...» для хода чёрных
  (1. ... Nd4), знаки !, ?, !!, ?!, +, #, оценки +-, -+, =, ±, ∓, ∞.
- Варианты в скобках сохраняй.

ТОЧНОСТЬ ВАЖНЕЕ СКОРОСТИ. Ходы — главная ценность файла.

Когда все файлы записаны, ответь коротко: список файлов и сколько решений в каждом.

## Что с этим делать дальше

Маркеры `[[TEST k]]` / `[[N n]]` / `[[CONT]]` позволяют собрать страницы
обратно в 600 решений и сразу проверить: тестов должно быть ровно 50,
в каждом ровно 12 решений с номерами 1…12. Если сходится — ни одна
страница не потеряна и не задвоена.

Дальше — `10_validate_vs_solutions.py`: ходы подставляются в позицию.
