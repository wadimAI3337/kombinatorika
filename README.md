# Комбинаторика

Шахматный тренажёр: сборники задач из книг, разбор своей партии движком Stockfish
и дебютный репертуар с интервальным повторением. Обычная статическая страница —
никакого сервера не нужно, достаточно GitHub Pages.

## Из чего состоит

| Файл | Что это |
|---|---|
| `index.html` | вёрстка и стили приложения |
| `app.js` | само приложение и все задачники (2,2 МБ) |
| `auth.js` | вход, регистрация и синхронизация сохранений |
| `auth.css` | стили окна входа |
| `stats.js` | экран «Статистика»: графики, карта активности, связка с lichess и chess.com |
| `stats.css` | стили этого экрана |
| `config.js` | два ключа от Supabase — **это и есть вся настройка** |
| `schema.sql` | SQL, который нужно один раз выполнить в Supabase |

Раньше всё это лежало в одном HTML-файле. Он сохранён как `original-backup.html`
(в репозиторий не попадает — см. `.gitignore`).

## 1. Выложить на GitHub Pages

### Если не хочется возиться с командной строкой

1. Зарегистрируйся на [github.com](https://github.com) и нажми **New repository**.
2. Имя — например `kombinatorika`, видимость **Public**, ничего не отмечай, **Create**.
3. На странице пустого репозитория нажми **uploading an existing file**.
4. Перетащи туда **всё содержимое** этой папки (файлы, не саму папку) и нажми **Commit changes**.
5. **Settings → Pages**: в разделе *Build and deployment* выбери Source **Deploy from a branch**,
   ветку `main`, папку `/ (root)`, **Save**.
6. Через пару минут обнови страницу — там появится ссылка вида
   `https://ТВОЙ-ЛОГИН.github.io/kombinatorika/`. Её можно давать кому угодно.

### Если через терминал

```bash
cd ~/Documents/kombinatorika
git init -b main
git add -A
git commit -m "Комбинаторика: тренажёр"
git remote add origin https://github.com/ТВОЙ-ЛОГИН/kombinatorika.git
git push -u origin main
```

Потом всё равно зайди в **Settings → Pages** и включи публикацию из ветки `main`.

Дальше любое изменение публикуется так:

```bash
git add -A && git commit -m "что поменял" && git push
```

### Важно: номер версии

GitHub Pages отдаёт файлы с `Cache-Control: max-age=600`, то есть браузер ещё
десять минут после публикации берёт старые `app.js` и `config.js` из кэша — и
человек видит смесь нового и старого. Чтобы этого не было, файлы подключены
с номером версии:

```html
<link rel="stylesheet" href="auth.css?v=9">
<link rel="stylesheet" href="stats.css?v=9">
<script src="config.js?v=9"></script>
<script src="auth.js?v=9"></script>
```

**Поменял что-нибудь в `app.js`, `auth.js`, `stats.js`, `auth.css`, `stats.css`
или `config.js` — подними номер во всех четырёх строчках `index.html`** и только
потом пушь. К `app.js` и `stats.js` тот же номер подставится сам.

> Сайт обязательно должен открываться по `https://` — Stockfish подгружается с CDN
> и по `file://` (просто двойным кликом по файлу) работать не будет.

## 2. Включить регистрацию и облачные сохранения

Пока `config.js` пустой, сайт работает как раньше: прогресс лежит в браузере,
кнопки входа нет. Чтобы появились аккаунты:

1. Зарегистрируйся на [supabase.com](https://supabase.com) и создай новый проект
   (бесплатного тарифа хватает с запасом). Регион выбирай поближе — например Frankfurt.
2. **SQL Editor → New query** — вставь целиком содержимое `schema.sql` и нажми **Run**.
   Так появится таблица сохранений и правило «каждый видит только своё».
3. **Project Settings → API** — скопируй оттуда два значения в `config.js`:

   ```js
   window.KOMBI_CONFIG = {
     SUPABASE_URL: "https://xxxxxxxxxxxx.supabase.co",
     SUPABASE_ANON_KEY: "eyJhbGciOiJIUzI1..."
   };
   ```

4. **Authentication → URL Configuration** — впиши в *Site URL* адрес своего сайта
   (`https://ТВОЙ-ЛОГИН.github.io/kombinatorika/`), а в *Redirect URLs* добавь его же.
   Без этого не будет работать ссылка восстановления пароля.
5. Залей обновлённый `config.js` на GitHub. В шапке сайта появится кнопка **Войти**.

### Про подтверждение почты

По умолчанию Supabase просит подтвердить адрес письмом, и на бесплатном тарифе
таких писем немного (несколько штук в час). Если хочется, чтобы регистрация
срабатывала сразу: **Authentication → Sign In / Providers → Email** и выключи
**Confirm email**. Для личного тренажёра это нормально; если сайтом будут
пользоваться посторонние — лучше оставить включённым.

### Ключ anon не секретный

`SUPABASE_ANON_KEY` специально сделан публичным, его видно в коде любого сайта на
Supabase. Данные защищает не он, а политики RLS из `schema.sql`: запрос вернёт
только строку того, кто вошёл. Поэтому `config.js` спокойно лежит в открытом
репозитории.

## Как устроена синхронизация

Приложение ничего не знает про аккаунты — оно как писало в `localStorage`, так и пишет.
Всё берёт на себя `auth.js`:

* **при загрузке страницы**, если есть вход, сохранения скачиваются из облака
  в `localStorage` — и только потом запускается `app.js`;
* **во время игры** любая запись по ключам `kombi`, `kombi-op`, `kombi-theme`,
  `kombi-autoan`, `kombi-stats`, `kombi-ext` через полторы секунды улетает в облако;
* **при первом входе на устройстве** локальный прогресс не затирается, а
  *сливается* с облачным: решённая задача остаётся решённой, звёзды берутся
  максимальные, варианты дебютов объединяются по идентификаторам;
* кэш разборов партий (`kombi-rv-*`) не синхронизируется — это временный результат
  работы движка, он весит много и легко считается заново.

Точка справа от почты в шапке показывает состояние: зелёная — всё сохранено,
мигающая оранжевая — сохраняю, серая — не получилось (наведи мышь, там будет причина).
В меню по клику на почту есть «Сохранить сейчас», «Загрузить из облака» и «Выйти».

Несколько вкладок с одним аккаунтом одновременно лучше не держать: побеждает та,
что записала последней.

Из консоли браузера доступен `kombiSync` — `kombiSync.snapshot()` покажет, что
именно уедет в облако, `kombiSync.flush()` отправит немедленно.

## Статистика

Отдельный экран, кнопка **Статистика** в шапке. Считает три вещи.

**Задачи здесь.** Приложение не помечает решённые задачи датой, поэтому `auth.js`
считает активность сам: на каждую запись прогресса сравнивает новое состояние с
предыдущим и прибавляет разницу к сегодняшнему дню в ключ `kombi-stats`. Код
самого приложения при этом не меняется.

**Рейтинг и партии.** Ники с lichess и chess.com вводятся внизу экрана.
Читаются только открытые данные, никаких паролей и токенов:

| Откуда | Что берём |
|---|---|
| `api.chess.com/pub/player/{ник}/stats` | текущий рейтинг, рекорд Puzzle Rush |
| `api.chess.com/pub/player/{ник}/games/{год}/{месяц}` | партии по дням и рейтинг после каждой |
| `lichess.org/api/user/{ник}` | рейтинг во всех контролях, рейтинг задач и сколько решено |
| `lichess.org/api/user/{ник}/activity` | по дням: партии с рейтингом до/после и решённые задачи с изменением рейтинга |

История рейтинга собирается из архивов партий, поэтому график показывает и те
дни, когда на сайт не заходили. В дни без партий рейтинг тянется ровной линией
без кружка — сразу видно, где был перерыв, а где вернулся и отыграл вечер.

**Про экспорт партий lichess.** `api/games/user/{ник}` использовать не стоит:
он ограничен («не больше одного запроса за раз»), легко отвечает 429, весит
сотни килобайт и про задачи не знает. Всё нужное отдаёт `activity` — пара
килобайт одним запросом, и в нём есть даже изменение рейтинга задач по дням.
`api/user/{ник}/rating-history` тоже не помощник: он закрыт и отдаёт пустой
массив для любого игрока, включая Карлсена.

**Чего нет.** Текущий тактический рейтинг chess.com публично не отдаётся,
только рекорд Puzzle Rush. Истории задач chess.com по дням нет.

Данные обновляются сами: при открытии сайта и при заходе на экран, но не чаще
раза в пятнадцать минут. Ник вводится один раз — он уезжает в облако вместе с
прогрессом и подхватывается на других устройствах.

### Цвета графиков

lichess `#2a78d6` / `#3987e5`, chess.com `#eb6834` / `#d95926` (светлая / тёмная
тема). Пара проверена на различимость при дальтонизме и на контраст к фону
приложения в обеих темах. Менять на глаз не стоит — проверку легко завалить.

## Работа над ошибками

Сделано по образцу «Learn from your mistakes» на lichess. После разбора партии
в правой панели, сразу под точностью, появляется кнопка **⚑ Разобрать свои
ошибки · N** — N это сколько раз ошибся ты сам (не соперник). Место выбрано
не случайно: у lichess и chess.com вход именно там, а в ряду серых кнопок над
доской его не находят. Дальше приложение показывает позиции перед
твоими ошибками и просит найти ход получше.

Пока ищешь ход, **стрелка лучшего хода и оценка на доске скрыты** — вместо
оценки стоит «?». Иначе ответ был бы написан прямо на доске.

**Как засчитывается ход.** Не за совпадение с первой линией движка, а за то,
что ход сам не является ошибкой. Логика и порог взяты из `retrospect/retroCtrl.ts`
в lila: совпал с линией движка или ставит мат — сразу зачёт; повторил ход из
партии — отказ; иначе позиция после хода считается движком (глубина 14) и
сравниваются шансы на победу.

Порог у lichess — `povDiff > -0.04`. Шкалы у нас разные: их `povChances` лежит
в −1…1 и `povDiff` делится пополам, наш `Wcp = 50 + 50*raw` даёт 0…100. Наша
потеря ровно в 100 раз больше их `povDiff`, поэтому порог здесь **4.0 пункта**.

Чего у нас нет по сравнению с lichess: они дополнительно принимают ход, если он
есть в дебютной базе мастеров (`openingUcis`), даже когда движок его не любит.
Сделать можно через открытый `explorer.lichess.ovh/masters?fen=…`.

Отказ показывает, насколько просел твой вариант и сколько было потеряно в
самой партии — сравнение полезнее, чем просто «неверно».

Есть «Показать решение» (открывает линию движка) и «Пропустить». В конце —
сколько нашёл сам с первой попытки.

Результаты идут в `kombi-stats` полями `drills` (сколько ошибок разобрано) и
`fixed` (сколько найдено с первой попытки), попадают в карту активности и в
карточку «Работа над ошибками» на экране статистики.

Почему это отдельная функция, а не просто ещё один задачник: в исследованиях
самостоятельный разбор стабильно оказывается сильнее связан с ростом рейтинга,
чем количество сыгранных партий.
