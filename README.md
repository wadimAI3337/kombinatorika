# Комбинаторика

Шахматный тренажёр: сборники задач из книг, разбор своей партии движком Stockfish
и дебютный репертуар с интервальным повторением. Обычная статическая страница —
никакого сервера не нужно, достаточно GitHub Pages.

## Из чего состоит

| Файл | Что это |
|---|---|
| `index.html` | вёрстка и стили приложения |
| `app.js` | само приложение и все задачники (2,2 МБ) |
| `auth.js` | вход, регистрация и синхронизация сохранений |
| `auth.css` | стили окна входа |
| `config.js` | два ключа от Supabase — **это и есть вся настройка** |
| `schema.sql` | SQL, который нужно один раз выполнить в Supabase |

Раньше всё это лежало в одном HTML-файле. Он сохранён как `original-backup.html`
(в репозиторий не попадает — см. `.gitignore`).

## 1. Выложить на GitHub Pages

### Если не хочется возиться с командной строкой

1. Зарегистрируйся на [github.com](https://github.com) и нажми **New repository**.
2. Имя — например `kombinatorika`, видимость **Public**, ничего не отмечай, **Create**.
3. На странице пустого репозитория нажми **uploading an existing file**.
4. Перетащи туда **всё содержимое** этой папки (файлы, не саму папку) и нажми **Commit changes**.
5. **Settings → Pages**: в разделе *Build and deployment* выбери Source **Deploy from a branch**,
   ветку `main`, папку `/ (root)`, **Save**.
6. Через пару минут обнови страницу — там появится ссылка вида
   `https://ТВОЙ-ЛОГИН.github.io/kombinatorika/`. Её можно давать кому угодно.

### Если через терминал

```bash
cd ~/Documents/kombinatorika
git init -b main
git add -A
git commit -m "Комбинаторика: тренажёр"
git remote add origin https://github.com/ТВОЙ-ЛОГИН/kombinatorika.git
git push -u origin main
```

Потом всё равно зайди в **Settings → Pages** и включи публикацию из ветки `main`.

Дальше любое изменение публикуется так:

```bash
git add -A && git commit -m "что поменял" && git push
```

### Важно: номер версии

GitHub Pages отдаёт файлы с `Cache-Control: max-age=600`, то есть браузер ещё
десять минут после публикации берёт старые `app.js` и `config.js` из кэша — и
человек видит смесь нового и старого. Чтобы этого не было, файлы подключены
с номером версии:

```html
<link rel="stylesheet" href="auth.css?v=2">
<script src="config.js?v=2"></script>
<script src="auth.js?v=2"></script>
```

**Поменял что-нибудь в `app.js`, `auth.js`, `auth.css` или `config.js` — подними
номер во всех трёх строчках `index.html`** (`v=2` → `v=3`) и только потом пушь.
К `app.js` тот же номер подставится сам, его прописывать не нужно.

> Сайт обязательно должен открываться по `https://` — Stockfish подгружается с CDN
> и по `file://` (просто двойным кликом по файлу) работать не будет.

## 2. Включить регистрацию и облачные сохранения

Пока `config.js` пустой, сайт работает как раньше: прогресс лежит в браузере,
кнопки входа нет. Чтобы появились аккаунты:

1. Зарегистрируйся на [supabase.com](https://supabase.com) и создай новый проект
   (бесплатного тарифа хватает с запасом). Регион выбирай поближе — например Frankfurt.
2. **SQL Editor → New query** — вставь целиком содержимое `schema.sql` и нажми **Run**.
   Так появится таблица сохранений и правило «каждый видит только своё».
3. **Project Settings → API** — скопируй оттуда два значения в `config.js`:

   ```js
   window.KOMBI_CONFIG = {
     SUPABASE_URL: "https://xxxxxxxxxxxx.supabase.co",
     SUPABASE_ANON_KEY: "eyJhbGciOiJIUzI1..."
   };
   ```

4. **Authentication → URL Configuration** — впиши в *Site URL* адрес своего сайта
   (`https://ТВОЙ-ЛОГИН.github.io/kombinatorika/`), а в *Redirect URLs* добавь его же.
   Без этого не будет работать ссылка восстановления пароля.
5. Залей обновлённый `config.js` на GitHub. В шапке сайта появится кнопка **Войти**.

### Про подтверждение почты

По умолчанию Supabase просит подтвердить адрес письмом, и на бесплатном тарифе
таких писем немного (несколько штук в час). Если хочется, чтобы регистрация
срабатывала сразу: **Authentication → Sign In / Providers → Email** и выключи
**Confirm email**. Для личного тренажёра это нормально; если сайтом будут
пользоваться посторонние — лучше оставить включённым.

### Ключ anon не секретный

`SUPABASE_ANON_KEY` специально сделан публичным, его видно в коде любого сайта на
Supabase. Данные защищает не он, а политики RLS из `schema.sql`: запрос вернёт
только строку того, кто вошёл. Поэтому `config.js` спокойно лежит в открытом
репозитории.

## Как устроена синхронизация

Приложение ничего не знает про аккаунты — оно как писало в `localStorage`, так и пишет.
Всё берёт на себя `auth.js`:

* **при загрузке страницы**, если есть вход, сохранения скачиваются из облака
  в `localStorage` — и только потом запускается `app.js`;
* **во время игры** любая запись по ключам `kombi`, `kombi-op`, `kombi-theme`,
  `kombi-autoan` через полторы секунды улетает в облако;
* **при первом входе на устройстве** локальный прогресс не затирается, а
  *сливается* с облачным: решённая задача остаётся решённой, звёзды берутся
  максимальные, варианты дебютов объединяются по идентификаторам;
* кэш разборов партий (`kombi-rv-*`) не синхронизируется — это временный результат
  работы движка, он весит много и легко считается заново.

Точка справа от почты в шапке показывает состояние: зелёная — всё сохранено,
мигающая оранжевая — сохраняю, серая — не получилось (наведи мышь, там будет причина).
В меню по клику на почту есть «Сохранить сейчас», «Загрузить из облака» и «Выйти».

Несколько вкладок с одним аккаунтом одновременно лучше не держать: побеждает та,
что записала последней.

Из консоли браузера доступен `kombiSync` — `kombiSync.snapshot()` покажет, что
именно уедет в облако, `kombiSync.flush()` отправит немедленно.
